# Laya Moderator

[English version](README.md)
[![CI](https://github.com/Romay777/laya-telegram-mod/actions/workflows/ci.yml/badge.svg)](https://github.com/Romay777/laya-telegram-mod/actions/workflows/ci.yml)

Self-hosted Telegram-бот, который проверяет каждое сообщение в группе AI-классификатором. Спам, рекламу и оскорбления он удаляет, а автора ограничивает по нарастающей лестнице наказаний.

> **Статус:** функциональность v1 реализована и покрыта тестами. Запуск из исходников через Docker — готовых сборок пока нет. То, что сознательно отложено, перечислено в [roadmap](docs/ROADMAP.md).

## Возможности

- **AI-модерация.** Бот проверяет текст, подписи к медиа и отредактированные сообщения. По умолчанию работает [Laya](https://huggingface.co/convaiinnovations/laya) — локальная модель на CPU в формате INT8 ONNX. Для каждого чата можно переключиться на облачный API [Jev](https://docs.typesafe.ai); если Jev перегружена или недоступна, бот автоматически откатывается на Laya и сообщает администраторам, когда бэкенд восстановится.
- **Две зоны уверенности.** Явные нарушения бот обрабатывает сам. Сомнительные сообщения уходят администраторам с кнопками «Наказать» и «Пропустить» — выигрывает первый клик. На неотвеченные оповещения через 24 часа бот закрывает вопрос сам.
- **Сначала режим наблюдения.** Новый чат стартует без действий: каждое срабатывание становится оповещением, ничего не удаляется и не ограничивается. Раз в 48 часов приходит сводка того, что бот сделал бы. Автомодерацию вы включаете, когда убедитесь, что ему можно доверять.
- **Настраиваемая лестница наказаний.** По умолчанию 1 час → 24 часа → навсегда. Каждое нарушение сгорает через 30 дней. Участник остаётся в чате, у него просто отбирается право писать.
- **Апелляции.** Ограниченный участник нажимает «Это ошибка». Администратор получает цитату удалённого сообщения и кнопки «Снять ограничение» и «Отклонить».
- **Свои тексты уведомлений.** Можно задать свой текст с полным форматированием и плейсхолдерами `{user}`, `{reason}`, `{duration}`, `{strike}`. Уведомления ограничены по частоте в каждом чате.
- **Интерфейс в одном сообщении.** Инлайн-меню меняется на месте при переходах между экранами, кнопки цветные (Bot API 9.4+). Внутри — экран статистики (окна 7 и 30 дней) и журнал нарушений с постраничной прокруткой и карточкой каждого нарушения.
- **Самостоятельный контроль жизненного цикла.** Если бот теряет права в чате, он приостанавливает модерацию и сообщает администраторам; при повторном добавлении настройки чата восстанавливаются.
- **Русский и английский.** Язык интерфейса администратора и язык каждого чата выбираются отдельно.

## Быстрый старт

Нужен Docker с Compose. Контейнеру локальной модели выделено до 3 ГБ RAM (сама INT8-модель занимает 1–2 ГБ); Postgres и бот добавляют несколько сотен мегабайт.

1. Создайте бота в [@BotFather](https://t.me/BotFather) и скопируйте токен.
2. Настройте и запустите:

   ```bash
   git clone https://github.com/Romay777/laya-telegram-mod.git
   cd laya-telegram-mod
   cp .env.example .env    # укажите BOT_TOKEN и POSTGRES_PASSWORD
   docker compose up -d --build
   ```

   Первая сборка скачивает зафиксированную версию чекпоинта Laya и экспортирует её в INT8 ONNX, поэтому идёт долго; дальше всё запечено в образ, и во время работы бот не обращается к Hugging Face.

3. Откройте бота в Telegram, нажмите **Start**, выберите язык и нажмите **Добавить в чат**. Telegram предложит выбрать супергруппу и сразу выдаст боту нужные права: удаление сообщений и ограничение участников.

### Jev вместо Laya или вместе с ней

Укажите `JEV_API_KEY` в `.env`. По умолчанию `JEV_BASE_URL` указывает на TypeSafe. Для OpenRouter поставьте `https://openrouter.ai/api/v1`; модель выбирается через `JEV_MODEL`. После этого бэкенд можно выбрать для каждого чата в настройках бота. Чтобы работать только через Jev без локальной модели, удалите `COMPOSE_PROFILES=laya` из `.env`.

Если для чата включён Jev, тексты его сообщений отправляются стороннему API.

## Настройка

В `.env` задаётся только необходимое: токен бота, пароль Postgres, подключение к Jev и уровень логирования. Всё остальное — пороги уверенности для каждой пары бэкенд/чувствительность, лимиты на уведомления, сроки хранения — живёт в [`src/bot/config.toml`](src/bot/config.toml), и у каждого значения есть значение по умолчанию. Чтобы переопределить файл, смонтируйте свою копию по тому же пути в контейнер `bot`.

## Разработка

Оба подпроекта на Python 3.12 с пакетным менеджером [uv](https://docs.astral.sh/uv/):

```bash
cd src/bot
uv sync
uv run pytest            # интеграционные и e2e-тесты поднимают настоящий Postgres 17 через testcontainers (нужен Docker)
uv run ruff check .

cd ../laya-server
uv run pytest -q
```

CI прогоняет те же проверки для обоих проектов на каждый push и pull request. Стратегия тестирования описана в [документе архитектуры](docs/ARCHITECTURE.md).
